# Docker 部署

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。

## 52Token 生图工作台

```bash
cd /home/api/sub2api-deploy/images
docker compose -f docker-compose.local.yml up -d --build
```

默认容器只监听本机：

```text
127.0.0.1:15731 -> container:3000
```

公网访问由 Nginx 域名配置代理到 `127.0.0.1:15731`。`/v1/images/*` 和 `/v1beta/models/*` 应继续代理到 sub2api，不能被工作台容器接管。

工作台默认预置两个渠道：

| 渠道 | 调用格式 | Base URL | 默认模型 |
| --- | --- | --- | --- |
| 52Token Image2 | OpenAI | `https://image.52token.org` | `gpt-image-2` |
| 52Token Gemini 生图 | Gemini | `https://image.52token.org` | `gemini-3.1-flash-image-preview`、`gemini-3-pro-image-preview`、`banana-2`、`banana-pro` |

用户首次使用时只需要在右上角配置中填入自己的分组 API Key，并选择对应生图模型。

## 使用发布镜像

如果已经有发布镜像，也可以直接运行：

```bash
docker compose up -d
```

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据说明

当前主应用镜像只启动 nginx 静态前端。画布、我的素材、生成记录和 AI API Key 默认保存在浏览器本地；第三方提示词由浏览器前端直连拉取并缓存到 IndexedDB，不需要额外挂载数据目录。
